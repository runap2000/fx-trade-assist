# FX TRADE ASSIST v2.8.0 改良候補

## ファイル
- server.js
- index.html
- sw.js
- package.json
- README.txt

既存リポジトリの `manifest.webmanifest` と `icon.svg` は削除・置換せず、そのまま残してください。今回のZIPは上記5ファイルの差し替え用です。

## 主な変更
- 5分・15分・1時間足の既存分析と、EMA / RSI / Stochastics / ATR の判定を維持
- 3時間足すべてが同方向で、反対側スコアが0のときだけ売買候補とする既存条件を維持
- 転換の兆し、トレンド転換、経済指標リスクがある場合は新規候補を「様子見」にして見送り理由を表示
- 米国・日本の経済指標を取得し、30分前・5分前の通知と発表後15分の警戒を実装
- 保有方向（買い・売り・保有なし）を手動登録し、逆方向への警戒を表示
- シグナル候補の参考エントリー・SL・TP1をサーバー保存し、受信価格でTP1/SL到達を自動判定
- LINE FXの実約定価格・数量・実際のSL/TP・決済損益は、別の手動台帳に記録（シグナル成績と混同しない）
- 注文の自動発注・変更・決済は行わない

## 自動勝敗判定の注意
シグナル基準の参考成績です。買いはBid、売りはAskを使ってTP1/SLの到達を判定します。LINE FXの実約定・スプレッド・滑り・手数料を再現するものではありません。価格配信の欠落やティック間の値動きによって、実際の到達順序と異なる可能性があります。実取引の損益はLINE FXの実績を別台帳に記録してください。

## 保存先
- シグナル自動判定履歴：`DATA_DIR/signal-journal.json`
- 保有方向：`DATA_DIR/position.json`
- Push購読：`DATA_DIR/subscriptions.json`
- LINE FX実取引台帳：利用端末のブラウザ `localStorage`

Railwayでサーバー側の履歴を維持するには、`DATA_DIR`（既定 `/data`）に永続ボリュームをマウントしてください。永続ボリュームがない場合、コンテナ交換時にサーバー側履歴が失われる可能性があります。実取引台帳は端末ブラウザ保存なので、ブラウザデータ消去・端末変更時は引き継がれません。

## 本番反映前に必要な確認
1. Railwayの永続ボリュームと `DATA_DIR` の設定を確認
2. 実際の経済指標API応答で、イベント時刻・重要度・米国/日本のデータ形式を確認
3. VAPID環境変数が登録済みであることを確認
4. ステージング環境で買い・売りのTP1/SL到達を模擬テスト
5. 価格配信切断・再接続・サーバー再起動後の履歴維持を確認
6. 既存PWAの manifest/icon を維持し、Service Worker更新と通知購読を確認
7. 現行v2.7.0の通信量ベースラインと比較するため、テスト前後の稼働時間・Network Egressを記録
